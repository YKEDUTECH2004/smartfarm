This page specifies a research-prototype extension. It is not endorsed by the MCP project and is not a certified safety standard.

1. 목적 / Purpose

표준 MCP의 tools/call은 요청을 받으면 곧바로 실행합니다. 물리 액추에이터(예: 관수 펌프)에서는 재전송된 명령, 지연된 명령, 오래된 센서값, 연속 실행, 장애 직후 실행이 실제 위험이 됩니다. 이 확장은 MCP 메시지 형식을 유지하면서, 서버(MCU)가 직접 강제하는 안전 필드와 규칙을 추가합니다.

A standard tools/call executes immediately. For physical actuators, retransmitted, delayed, stale-input, back-to-back and post-fault commands are real hazards. This extension keeps MCP wire format and adds safety fields and rules that the device itself enforces.

2. 기능 공개 / Capability advertisement

서버는 server/discover 결과의 capabilities.extensions에 정책값을 공개합니다. 클라이언트는 이 값을 보고 호출 흐름을 정합니다.

"capabilities": {
  "tools": {}, "resources": {},
  "extensions": {
    "io.github.ykedutech2004/actuator-safety": {
      "version": "0.1",
      "approval_ttl_ms": 2000,
      "sensor_freshness_ms": 500,
      "cooldown_ms": 10000,
      "max_duration_ms": 5000,
      "fault_lockout": true
    }
  }
}

3. 안전 규칙 / Safety rules (E1–E8)

ID규칙서버 동작
E1Command identifier (idempotency)command_id(1–16자)를 일정 시간 보관하고, 같은 ID의 재요청은 실행하지 않고 REJECTED_DUPLICATE로 응답
E2Two-phase approval with TTLirrigation_prepare가 1회용 approval_token을 발급하고, irrigation_run은 유효한 토큰으로만 실행. TTL은 서버 시계 기준(시계 동기화 불필요). 만료·재사용 토큰 거부
E3Sensor freshness판단에 쓴 센서 표본이 sensor_freshness_ms보다 오래되면 REJECTED_STALE_SENSOR
E4Cooldown interlock직전 작동 종료 후 cooldown_ms 안의 요청은 REJECTED_COOLDOWN
E5Fault lockouthard cutoff 등 작동 장애가 나면 lockout. 해제 전 모든 실행 요청은 REJECTED_LOCKOUT
E6Capability advertisement§2의 정책값 공개
E7Structured reason codes거부 시 structuredContent에 outcome, reason_code, 관련 수치(sensor_age_ms, cooldown_remaining_ms)를 포함
E8Safety state resourceresource://smartfarm/safety: lockout 여부, cooldown 잔여, 유효 토큰 수

기본 안전(모든 서버에 공통): 입력 범위 검증(duration_ms 100–5000 → -32602), 펌프 사용 중 거부, 요청 시간 + 100 ms 초과 시 hard cutoff, 표준 헤더(Mcp-Method, Mcp-Name) 검증. 이 확장은 이 기본 안전 위에 추가됩니다.

4. 도구 / Tools

irrigation_prepare

arguments: { "duration_ms": 100..5000 }
result.structuredContent: {
  "outcome": "APPROVED",
  "approval_token": "3f9a0c21",
  "expires_in_ms": 2000,
  "duration_ms": 1000
}
// lockout / cooldown 중이면 발급하지 않고 해당 outcome으로 응답

irrigation_run

arguments: { "approval_token": "3f9a0c21", "command_id": "job-001" }
result.structuredContent: {
  "job_id": "job-001", "outcome": "EXECUTED",
  "duration_ms": 1000, "moisture_pct": 25, "pump_state": "OFF",
  "reason_code": 0, "sensor_age_ms": 21
}

irrigation_stop

arguments: { "job_id": "job-001" }  →  outcome: STOPPED | ALREADY_STOPPED | JOB_MISMATCH

안전 거부는 JSON-RPC 오류가 아니라 정상 tool 결과(isError: true + outcome)로 반환합니다. 형식 오류만 JSON-RPC 오류(-32602, -32020 등)로 반환합니다.

6. MCP 2026-07-28과의 관계 / Conformance scope

이 확장을 쓰는 참조 구현(ESP32, 4개 FreeRTOS agent)은 MCP 2026-07-28의 stateless Streamable HTTP, 표준 헤더(SEP-2243), server/discover(SEP-2575), 확장 공개(SEP-2133)를 따르는 제한된 부분 구현입니다. 캐시 필드(ttlMs, cacheScope), resultType, HTTP 상태 코드 세분화, Origin 검증은 구현하지 않았습니다.

7. 알려진 한계 / Known limitations

  • 2단계 승인은 관수 1건당 HTTP 왕복을 1회 늘립니다. 네트워크 지연이 TTL을 넘으면 정상 명령도 만료로 거부될 수 있습니다(안전성과 가용성의 트레이드오프).
  • 인증·암호화(토큰 서명, TLS)는 범위 밖입니다. 폐쇄 LAN 시험 환경을 전제로 합니다.
  • 정책값(TTL, freshness, cooldown)은 연구용 값이며 실제 농업 현장에 맞춘 값이 아닙니다.
